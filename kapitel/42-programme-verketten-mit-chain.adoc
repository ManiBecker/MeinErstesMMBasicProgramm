== Programme verketten mit CHAIN

image::bilder/42_programme_verketten.jpg[align=center]

=== Das lernst du

In diesem Kapitel lernst du:

* was `CHAIN` macht,
* wie du mehrere Programme miteinander verbindest,
* wie Variablen beim Programmwechsel erhalten bleiben,
* wie du mit `MM.CMDLINE$` zusätzliche Informationen an das nächste Programm übergibst,
* wie du ein gemeinsames Menü für deine Programme erstellst und
* wann Daten zusätzlich in einer Datei gespeichert werden sollten.

Am Ende des Kapitels kannst du mehrere eigenständige MMBasic-Programme zu
einer gemeinsamen Anwendung verbinden und dabei Daten von einem Programm an
das nächste weitergeben.

=== Ein gemeinsames Menü

In den bisherigen Kapiteln hast du bereits mehrere Programme entwickelt,
zum Beispiel:

* Pong,
* Senso,
* Little Professor und
* die Bahnhofsuhr.

Wäre es nicht praktisch, wenn du alle diese Programme über ein gemeinsames
Hauptmenü starten könntest?

Genau dafür eignet sich der Befehl `CHAIN`.

Mit `CHAIN` kann ein laufendes BASIC-Programm ein anderes BASIC-Programm laden
und sofort starten. Dabei bleibt der Variablenbereich erhalten. Auf diese Weise
lassen sich größere Anwendungen auf mehrere Programme verteilen, ohne dass alle
Daten beim Wechsel verloren gehen.

Ein solches Projekt könnte beispielsweise aus folgenden Dateien bestehen:

[source]
----
HAUPTMENU.BAS
PONG.BAS
SENSO.BAS
LITTLEPROFESSOR.BAS
UHR.BAS
RECHNER.BAS
----

=== Was macht CHAIN?

Die grundlegende Syntax lautet:

[source,basic]
----
CHAIN fname$ [cmdline$]
----

`fname$` bezeichnet das BASIC-Programm, das geladen und gestartet werden soll.
Optional kann zusätzlich mit `cmdline$` eine Zeichenkette an das neue Programm
übergeben werden.

Ein einfaches Beispiel:

[source,basic]
----
CHAIN "PONG.BAS"
----

Das aktuell laufende Programm wird durch `PONG.BAS` ersetzt und dieses sofort
gestartet.

Der wichtige Unterschied zu einem vollständigen Neustart ist: Der vorhandene
Variablenbereich bleibt erhalten.

[IMPORTANT]
====
Beim Wechsel mit `CHAIN` bleiben die Variablen des bisherigen Programms erhalten.
Das neue Programm kann diese Variablen deshalb weiterverwenden.
====

=== Variablen bleiben erhalten

Nehmen wir an, ein erstes Programm setzt einige Werte:

[source,basic]
----
punkte = 100
spieler$ = "Manfred"

CHAIN "SPIEL2.BAS"
----

Im Programm `SPIEL2.BAS` können diese Variablen direkt weiterverwendet werden:

[source,basic]
----
PRINT "Spieler: "; spieler$
PRINT "Punkte: "; punkte
----

Die Ausgabe könnte so aussehen:

[source]
----
Spieler: Manfred
Punkte: 100
----

Damit eignet sich `CHAIN` nicht nur zum Starten eines anderen Programms, sondern
auch dazu, größere Programme in mehrere Teile aufzuteilen und dabei gemeinsame
Daten weiterzugeben.

[NOTE]
====
Damit das zuverlässig funktioniert, sollten Variablen, die zwischen mehreren
Programmen verwendet werden, in allen beteiligten Programmen mit demselben Namen
und demselben Datentyp benutzt werden.
====

=== Zusätzliche Parameter mit MM.CMDLINE$

Neben dem erhaltenen Variablenbereich kann `CHAIN` dem nächsten Programm noch
eine zusätzliche Zeichenkette übergeben.

Beispiel:

[source,basic]
----
CHAIN "SPIEL.BAS", "LEVEL=2"
----

Im gestarteten Programm steht diese Zeichenkette in `MM.CMDLINE$` zur Verfügung:

[source,basic]
----
PRINT MM.CMDLINE$
----

Die Ausgabe lautet:

[source]
----
LEVEL=2
----

`MM.CMDLINE$` eignet sich beispielsweise für:

* Startoptionen,
* Dateinamen,
* einen gewünschten Spielmodus oder
* andere kurze Parameter, die das neue Programm beim Start auswerten soll.

Ein einfaches Beispiel wäre:

[source,basic]
----
IF MM.CMDLINE$ = "SCHWER" THEN
  PRINT "Schwieriger Spielmodus"
ELSE
  PRINT "Normaler Spielmodus"
ENDIF
----

=== CHAIN oder RUN?

Auf den ersten Blick scheint `CHAIN` dem Befehl `RUN` ähnlich zu sein. Beide
können ein BASIC-Programm starten, sie werden aber für unterschiedliche Zwecke
eingesetzt.

`RUN` wird häufig an der MMBasic-Eingabeaufforderung verwendet, um ein Programm
zu starten:

[source,basic]
----
RUN "PONG.BAS"
----

`CHAIN` wird dagegen innerhalb eines laufenden Programms verwendet, wenn die
Programmausführung mit einem anderen BASIC-Programm fortgesetzt werden soll:

[source,basic]
----
IF taste$ = "P" THEN
  CHAIN "PONG.BAS"
ENDIF
----

Der besondere Vorteil von `CHAIN` besteht darin, dass der Variablenbereich beim
Programmwechsel erhalten bleibt.

=== Ein einfaches Hauptmenü

Erstellen wir ein Menü, über das sich einige unserer bisherigen Programme
starten lassen.

Speichere das folgende Programm als `HAUPTMENU.BAS`:

[source,basic]
----
CLS

PRINT "========================"
PRINT "   MMBASIC-SAMMLUNG"
PRINT "========================"
PRINT
PRINT "1 - Pong"
PRINT "2 - Senso"
PRINT "3 - Little Professor"
PRINT "4 - Bahnhofsuhr"
PRINT "5 - Rechner"
PRINT
PRINT "0 - Ende"

INPUT "Auswahl"; wahl

SELECT CASE wahl

  CASE 1
    CHAIN "PONG.BAS", "HAUPTMENU"

  CASE 2
    CHAIN "SENSO.BAS", "HAUPTMENU"

  CASE 3
    CHAIN "LITTLEPROFESSOR.BAS", "HAUPTMENU"

  CASE 4
    CHAIN "UHR.BAS", "HAUPTMENU"

  CASE 5
    CHAIN "RECHNER.BAS", "HAUPTMENU"

  CASE 0
    END

  CASE ELSE
    PRINT "Ungültige Auswahl"

END SELECT
----

Wählt der Benutzer einen Menüpunkt aus, lädt `CHAIN` das zugehörige Programm
und startet es. Zusätzlich erhält das gestartete Programm in diesem Beispiel
über `MM.CMDLINE$` die Information, dass es aus dem Hauptmenü aufgerufen wurde.

=== Die Struktur des Projekts

Die Dateien können gemeinsam in einem Projektverzeichnis abgelegt werden:

[source]
----
MMBASIC-SAMMLUNG
│
├── HAUPTMENU.BAS
├── PONG.BAS
├── SENSO.BAS
├── LITTLEPROFESSOR.BAS
├── UHR.BAS
└── RECHNER.BAS
----

Der Benutzer startet nur das Hauptmenü:

[source,basic]
----
RUN "HAUPTMENU.BAS"
----

Alle weiteren Programme werden anschließend über das Menü aufgerufen.

=== Zurück zum Hauptmenü

Damit eine zusammenhängende Anwendung entsteht, sollten die aufgerufenen
Programme wieder zum Hauptmenü zurückkehren können.

Am Ende eines Spiels könnte beispielsweise stehen:

[source,basic]
----
PRINT
PRINT "Beliebige Taste für das Hauptmenü ..."

DO
LOOP UNTIL INKEY$ <> ""

CHAIN "HAUPTMENU.BAS"
----

Nach dem Tastendruck wird das Hauptmenü wieder geladen und gestartet.

Da der Variablenbereich erhalten bleibt, könnten dabei beispielsweise auch ein
Punktestand, ein Spielername oder eine Einstellung weitergegeben werden.

=== CHAIN möglichst auf Programmebene verwenden

Das PicoMite-Handbuch empfiehlt, `CHAIN` auf der obersten Programmebene zu
verwenden und möglichst nicht innerhalb einer Subroutine aufzurufen.

[IMPORTANT]
====
Verwende `CHAIN` nach Möglichkeit im Hauptablauf deines Programms und nicht aus
einer `SUB` oder `FUNCTION` heraus.
====

Eine gute Struktur ist beispielsweise:

[source,basic]
----
DO
  k$ = INKEY$
LOOP UNTIL k$ <> ""

IF k$ = "1" THEN CHAIN "SPIEL1.BAS"
IF k$ = "2" THEN CHAIN "SPIEL2.BAS"
----

So bleibt der Programmablauf übersichtlich und der Programmwechsel findet auf
der obersten Ebene statt.

=== Vorteile von CHAIN

Die Verbindung mehrerer Programme bietet einige Vorteile:

* Die einzelnen Programme bleiben überschaubar.
* Jedes Programm kann unabhängig entwickelt und getestet werden.
* Der Variablenbereich bleibt beim Wechsel erhalten.
* Daten können ohne zusätzliche Datei an das nächste Programm weitergegeben werden.
* Mit `MM.CMDLINE$` können zusätzliche Startparameter übergeben werden.
* Einzelne Programme können ausgetauscht oder erweitert werden.
* Ein zentrales Menü kann mehrere Programme zu einer gemeinsamen Anwendung verbinden.

[TIP]
====
`CHAIN` eignet sich besonders für größere Anwendungen, die in mehrere eigenständige
Programmteile aufgeteilt werden sollen.

Sollen dagegen mehrere Programme vor allem dieselben Unterprogramme oder Funktionen
verwenden, ist häufig die MMBasic-Library die bessere Wahl.
====

=== Ein Beispiel aus der Praxis

Auch eine kleine Werkzeugsammlung lässt sich mit `CHAIN` aufbauen:

[source]
----
TOOLS
│
├── MENU.BAS
├── TABELLE.BAS
├── UHR.BAS
├── RECHNER.BAS
└── NOTIZEN.BAS
----

Das Menü übernimmt nur die Auswahl. Die einzelnen Programme können separat
entwickelt und getestet werden. Gemeinsame Variablen, zum Beispiel Einstellungen
oder ein Benutzername, können beim Wechsel erhalten bleiben.

=== Wann trotzdem eine Datei sinnvoll ist

Da `CHAIN` den Variablenbereich erhält, müssen Werte nicht allein wegen eines
Programmwechsels in einer Datei gespeichert werden.

Eine Datei ist aber weiterhin sinnvoll, wenn Daten dauerhaft erhalten bleiben
sollen, zum Beispiel:

* nach dem Ende der Programmkette,
* nach einem Neustart des PicoMite,
* nach dem Ausschalten oder
* wenn die Daten später von einem anderen Programm erneut geladen werden sollen.

==== Beispiel: Spielstand dauerhaft speichern

[source,basic]
----
OPEN "PUNKTE.TXT" FOR OUTPUT AS #1
PRINT #1, punkte
CLOSE #1
----

Ein anderes Programm kann den gespeicherten Wert später wieder einlesen:

[source,basic]
----
OPEN "PUNKTE.TXT" FOR INPUT AS #1
INPUT #1, punkte
CLOSE #1

PRINT "Punkte: "; punkte
----

Der Unterschied ist wichtig: `CHAIN` erhält Werte während der laufenden
Programmkette. Eine Datei speichert sie dauerhaft auf dem Laufwerk.

=== CHAIN und Verzeichnisse

`CHAIN` kann auch mit Pfadangaben verwendet werden.

Beispiel:

[source,basic]
----
CHAIN "A:/SPIELE/PONG.BAS"
----

oder bei einer entsprechend eingerichteten SD-Karte:

[source,basic]
----
CHAIN "B:/TOOLS/UHR.BAS"
----

Dadurch lassen sich auch größere Programmsammlungen übersichtlich in
verschiedenen Verzeichnissen organisieren.

Wie du Laufwerke und Verzeichnisse verwendest, hast du bereits im vorherigen
Kapitel kennengelernt.

=== Historischer Hintergrund

Schon viele klassische BASIC-Systeme kannten Möglichkeiten, umfangreichere
Anwendungen auf mehrere Programme aufzuteilen.

Auf Computern mit wenig Speicher war das besonders nützlich, weil nicht immer
der gesamte Programmcode gleichzeitig im Speicher liegen musste. MMBasic führt
dieses bewährte Konzept mit `CHAIN` fort und erlaubt dabei zusätzlich, den
Variablenbereich zwischen den Programmteilen zu erhalten.

=== Praxisprojekt: Eine kleine Programmkette

Zum Abschluss erstellen wir drei kleine Programme, mit denen du die wichtigsten
Eigenschaften von `CHAIN` direkt ausprobieren kannst.

==== 42_chain_start.bas

[source,basic]
----
CLS

spieler$ = "Manfred"
punkte = 100

PRINT "Startprogramm"
PRINT "Spieler: "; spieler$
PRINT "Punkte:  "; punkte
PRINT
PRINT "Weiter mit beliebiger Taste ..."

DO
LOOP UNTIL INKEY$ <> ""

CHAIN "42_chain_spiel.bas", "LEVEL=2"
----

Das Programm legt zwei Variablen an und startet anschließend
`42_chain_spiel.bas`. Zusätzlich wird mit `LEVEL=2` ein Parameter übergeben.

==== 42_chain_spiel.bas

[source,basic]
----
CLS

PRINT "Spielprogramm"
PRINT "Spieler: "; spieler$
PRINT "Punkte:  "; punkte
PRINT "Parameter: "; MM.CMDLINE$
PRINT

punkte = punkte + 50

PRINT "50 Punkte gewonnen!"
PRINT "Neuer Punktestand: "; punkte
PRINT
PRINT "Weiter mit beliebiger Taste ..."

DO
LOOP UNTIL INKEY$ <> ""

CHAIN "42_chain_ende.bas"
----

Hier werden die Variablen des ersten Programms weiterverwendet. Der Punktestand
wird verändert und bleibt auch beim nächsten `CHAIN` erhalten.

==== 42_chain_ende.bas

[source,basic]
----
CLS

PRINT "Endprogramm"
PRINT
PRINT "Spieler: "; spieler$
PRINT "Endstand: "; punkte
PRINT
PRINT "Die Variablen wurden über die gesamte"
PRINT "Programmkette hinweg erhalten."
----

Wenn alles funktioniert, zeigt das letzte Programm weiterhin den Spielernamen
und den inzwischen erhöhten Punktestand an.

Damit kannst du direkt beobachten, dass `CHAIN` den Variablenbereich nicht
löscht, sondern an das nächste Programm weitergibt.

=== Tipps aus der Praxis

* Verwende `CHAIN`, wenn eine Anwendung sinnvoll in mehrere BASIC-Programme aufgeteilt werden kann.
* Nutze den erhaltenen Variablenbereich, um Daten an das nächste Programm weiterzugeben.
* Verwende `MM.CMDLINE$`, wenn du dem nächsten Programm gezielt einen zusätzlichen Startparameter mitgeben möchtest.
* Verwende `CHAIN` möglichst auf der obersten Programmebene und nicht innerhalb einer Subroutine.
* Teste jedes Programm zunächst einzeln.
* Verwende aussagekräftige Datei- und Verzeichnisnamen.
* Speichere Daten in einer Datei, wenn sie auch nach dem Ende der Programmkette oder nach einem Neustart erhalten bleiben sollen.
* Plane bei größeren Projekten frühzeitig eine klare Verzeichnisstruktur.

=== Probier's selbst!

. Erstelle ein Startprogramm und ein zweites BASIC-Programm.
. Lege im Startprogramm eine numerische Variable und eine Stringvariable an.
. Starte das zweite Programm mit `CHAIN` und gib dort beide Variablen aus.
. Übergib zusätzlich einen Textparameter und zeige ihn mit `MM.CMDLINE$` an.
. Verändere im zweiten Programm einen Wert und starte mit `CHAIN` ein drittes Programm.
. Prüfe, ob der geänderte Wert dort weiterhin vorhanden ist.
. Erweitere das Beispiel anschließend zu einem kleinen Hauptmenü.

=== Zusammenfassung

In diesem Kapitel hast du gelernt:

* Programme mit `CHAIN` zu starten,
* mehrere BASIC-Programme miteinander zu verbinden,
* dass der Variablenbereich beim Programmwechsel erhalten bleibt,
* zusätzliche Parameter über `MM.CMDLINE$` zu übergeben,
* ein gemeinsames Menü zu erstellen,
* `CHAIN` möglichst auf der obersten Programmebene einzusetzen und
* wann Daten zusätzlich dauerhaft in einer Datei gespeichert werden sollten.

`CHAIN` startet nicht einfach nur ein anderes Programm. Der Befehl erlaubt es,
eine größere Anwendung auf mehrere BASIC-Dateien aufzuteilen und dabei den
Variablenbereich weiterzuführen. Dadurch eignet sich `CHAIN` besonders für
Menüsysteme, Spiele mit mehreren Programmteilen und größere Programmsammlungen.
