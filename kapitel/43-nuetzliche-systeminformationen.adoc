== Nützliche Systeminformationen

image::bilder/43_systeminformationen.jpg[align=center]

=== Das lernst du

In diesem Kapitel lernst du:

* wichtige Systeminformationen abzufragen
* Bildschirmgrößen automatisch zu erkennen
* Informationen über Speicher, Laufwerke und Dateien auszulesen
* die Funktionen `MM.INFO()` und `MM.INFO$()` zu verwenden
* Programme an unterschiedliche Hardware und Laufzeitbedingungen anzupassen

Am Ende des Kapitels kannst du Programme schreiben, die wichtige Eigenschaften ihrer Umgebung selbst ermitteln und darauf reagieren.

=== Warum Systeminformationen wichtig sind

In den bisherigen Kapiteln haben wir häufig feste Werte verwendet.

Beispielsweise:

[source,basic]
----
CIRCLE 400, 300, 100
----

Das funktioniert zwar, setzt aber eine bestimmte Bildschirmauflösung voraus.

Eleganter ist es, Informationen direkt vom System abzufragen. Dadurch werden Programme flexibler und lassen sich leichter an unterschiedliche Geräte oder Einstellungen anpassen.

=== Bildschirmauflösung ermitteln

Eine der wichtigsten Informationen ist die aktuelle Bildschirmgröße.

MMBasic stellt dafür zwei schreibgeschützte Systemvariablen bereit:

[source,basic]
----
PRINT MM.HRES
PRINT MM.VRES
----

Dabei bedeutet:

[cols="1,3"]
|===
|Variable |Bedeutung

|`MM.HRES`
|Bildschirmbreite in Pixeln

|`MM.VRES`
|Bildschirmhöhe in Pixeln
|===

Je nach eingestelltem Grafikmodus können die Werte unterschiedlich sein.

Ein Programm kann dadurch automatisch auf die aktuelle Auflösung reagieren.

=== Objekte zentrieren

Anstatt feste Koordinaten zu verwenden:

[source,basic]
----
CIRCLE 400, 300, 100
----

kann das Objekt automatisch zentriert werden:

[source,basic]
----
CIRCLE MM.HRES / 2, MM.VRES / 2, 100
----

Dieses Verfahren haben wir bereits in mehreren Grafikprojekten verwendet.

=== Die aktuelle Position

Auch die aktuelle Ausgabe- beziehungsweise Grafikposition kann abgefragt werden.

Dafür gibt es:

[source,basic]
----
PRINT MM.INFO(HPOS)
PRINT MM.INFO(VPOS)
----

`MM.INFO(HPOS)` liefert die aktuelle horizontale Position und `MM.INFO(VPOS)` die aktuelle vertikale Position in Pixeln. Die Werte beziehen sich auf die Position nach dem letzten Grafik- oder `PRINT`-Befehl.

=== Informationen mit MM.INFO()

Viele weitere Systeminformationen können mit `MM.INFO()` abgefragt werden.

Grundsätzlich gibt es zwei Schreibweisen:

[source,basic]
----
MM.INFO(parameter)
MM.INFO$(parameter)
----

Beide Varianten können laut PicoMite-Handbuch grundsätzlich untereinander verwendet werden. Gute Programmierpraxis ist jedoch, die Variante passend zum zurückgegebenen Datentyp zu wählen:

* `MM.INFO()` für numerische Werte
* `MM.INFO$()` für Zeichenketten

Im weiteren Verlauf dieses Kapitels verwenden wir daher jeweils die passende Schreibweise.

=== Freien MMBasic-Speicher anzeigen

Ein häufig interessanter Wert ist der noch freie MMBasic-Heap.

[source,basic]
----
PRINT MM.INFO(HEAP)
----

Der MMBasic-Heap wird unter anderem für Strings, Arrays und verschiedene interne Puffer verwendet. `MM.INFO(HEAP)` liefert den noch freien Speicher in Byte.

Daneben gibt es mit `MM.INFO(SYSTEM HEAP)` auch eine Abfrage für den freien System-Heap. Für normale BASIC-Programme ist jedoch meist `MM.INFO(HEAP)` die interessantere Information.

=== CPU-Geschwindigkeit anzeigen

Die aktuelle CPU-Geschwindigkeit kann mit `MM.INFO$(CPUSPEED)` abgefragt werden:

[source,basic]
----
PRINT MM.INFO$(CPUSPEED)
----

Auf dem für dieses Tutorial verwendeten PicoMite HDMI/USB ergibt sich beispielsweise:

[source]
----
252000000
----

Das entspricht einer CPU-Geschwindigkeit von 252 MHz.

Obwohl die Ausgabe nur aus Ziffern besteht, liefert `MM.INFO$(CPUSPEED)` laut Handbuch eine Zeichenkette zurück.

=== Firmware-Version anzeigen

Mit `MM.INFO(VERSION)` lässt sich die installierte PicoMite-Firmwareversion ermitteln:

[source,basic]
----
PRINT MM.INFO(VERSION)
----

Bei unserem Testsystem lautet die Ausgabe:

[source]
----
6.0301
----

Diese Information kann beispielsweise bei der Fehlersuche hilfreich sein, wenn sich Befehle oder Funktionen zwischen Firmwareversionen geändert haben.

=== Ursache des letzten Starts anzeigen

Interessant ist auch die Frage, warum der Pico zuletzt neu gestartet wurde.

[source,basic]
----
PRINT MM.INFO$(BOOT)
----

Bei einem Neustart über den Reset-Taster erhielten wir:

[source]
----
Reset Switch
----

Je nach Ursache sind auch andere Rückgabewerte möglich, beispielsweise `Power On`, `Restart`, `S/W Watchdog`, `H/W Watchdog` oder `Firmware update`.

=== Laufzeit seit dem Start

Mit `MM.INFO(UPTIME)` kann die bisherige Laufzeit seit dem letzten Start abgefragt werden:

[source,basic]
----
PRINT MM.INFO(UPTIME)
----

Der Wert wird in Sekunden als Fließkommazahl zurückgegeben.

Damit lässt sich beispielsweise feststellen, wie lange ein Programm oder ein PicoMite-System bereits läuft.

=== Aktives Laufwerk anzeigen

Das aktuell aktive Laufwerk wird mit `MM.INFO$(DRIVE)` ermittelt:

[source,basic]
----
PRINT MM.INFO$(DRIVE)
----

Mögliche Rückgabewerte sind:

[source]
----
A:
----

oder:

[source]
----
B:
----

Wie wir in Kapitel 41 gesehen haben, steht `A:` beim PicoMite für das Flash-Dateisystem und `B:` für die SD-Karte, sofern diese eingerichtet ist.

=== Verfügbaren Speicherplatz anzeigen

Der freie Speicherplatz auf dem aktuell aktiven Laufwerk wird mit `MM.INFO(FREE SPACE)` ermittelt:

[source,basic]
----
PRINT MM.INFO(FREE SPACE)
----

Der Rückgabewert wird in Byte angegeben.

=== Größe des Laufwerks anzeigen

Die Gesamtkapazität des aktiven Laufwerks liefert `MM.INFO(DISK SIZE)`:

[source,basic]
----
PRINT MM.INFO(DISK SIZE)
----

Auch dieser Wert wird in Byte zurückgegeben.

Damit lassen sich beispielsweise freier und belegter Speicherplatz berechnen.

=== Existiert eine Datei?

Oft soll vor dem Öffnen einer Datei geprüft werden, ob sie tatsächlich vorhanden ist.

Dafür gibt es `MM.INFO(EXISTS FILE ...)`:

[source,basic]
----
IF MM.INFO(EXISTS FILE "PONG.BAS") = 1 THEN
  PRINT "Datei gefunden"
ELSE
  PRINT "Datei nicht gefunden"
ENDIF
----

Die Funktion liefert nicht nur wahr oder falsch, sondern unterscheidet drei Fälle:

[cols="1,3"]
|===
|Rückgabewert |Bedeutung

|`1`
|Die Datei existiert.

|`-1`
|Der angegebene Name bezeichnet ein Verzeichnis.

|`0`
|Die Datei beziehungsweise das Verzeichnis wurde nicht gefunden.
|===

Deshalb prüfen wir im Beispiel ausdrücklich auf `= 1`.

=== Existiert ein Verzeichnis?

Auch Verzeichnisse können geprüft werden:

[source,basic]
----
IF MM.INFO(EXISTS DIR "SPIELE") THEN
  PRINT "Verzeichnis vorhanden"
ENDIF
----

`MM.INFO(EXISTS DIR ...)` liefert einen booleschen Wert zurück, der angibt, ob das Verzeichnis vorhanden ist.

=== Das aktuelle Verzeichnis

Das aktuelle Arbeitsverzeichnis lässt sich mit `CWD$` anzeigen:

[source,basic]
----
PRINT CWD$
----

`CWD` steht für _Current Working Directory_.

Eine mögliche Ausgabe wäre beispielsweise:

[source]
----
/SPIELE
----

Das aktuelle Arbeitsverzeichnis ist besonders wichtig, wenn Programme mit relativen Dateinamen arbeiten.

=== Informationen über das aktuelle Programm

Der PicoMite kann auch Informationen über das aktuell geladene BASIC-Programm bereitstellen.

Mit `MM.INFO$(CURRENT)` wird der Name des aktuellen Programms abgefragt:

[source,basic]
----
PRINT MM.INFO$(CURRENT)
----

`MM.INFO$(PATH)` liefert den Pfad, aus dem das Programm geladen wurde:

[source,basic]
----
PRINT MM.INFO$(PATH)
----

Wurde kein Programm aus einer Datei geladen, können beide Funktionen `NONE` zurückgeben.

Bei unserem Test direkt nach einer Eingabe an der Eingabeaufforderung erhielten wir beispielsweise:

[source]
----
NONE
NONE
----

Diese Informationen können in größeren Projekten nützlich sein, wenn ein Programm wissen muss, aus welcher Datei beziehungsweise aus welchem Verzeichnis es gestartet wurde.

=== Beispiel: Systemübersicht

Mit den bisher kennengelernten Funktionen lässt sich bereits eine kleine Systemübersicht erstellen:

[source,basic]
----
CLS

PRINT "Systeminformationen"
PRINT "-------------------"
PRINT
PRINT "Breite      : "; MM.HRES
PRINT "Hoehe       : "; MM.VRES
PRINT "CPU-Speed   : "; MM.INFO$(CPUSPEED)
PRINT "Version     : "; MM.INFO(VERSION)
PRINT "Boot        : "; MM.INFO$(BOOT)
PRINT "Uptime      : "; MM.INFO(UPTIME); " s"
PRINT "Heap frei   : "; MM.INFO(HEAP)
PRINT "Laufwerk    : "; MM.INFO$(DRIVE)
PRINT "Verzeichnis : "; CWD$
PRINT "Programm    : "; MM.INFO$(CURRENT)
PRINT "Pfad        : "; MM.INFO$(PATH)
----

Damit erhält man auf einen Blick einige der wichtigsten Informationen über das laufende PicoMite-System.

=== Programme automatisch anpassen

Mit Systeminformationen lassen sich Programme deutlich flexibler gestalten.

Ein einfaches Beispiel ist die Anpassung an die Bildschirmbreite:

[source,basic]
----
IF MM.HRES >= 1024 THEN
  PRINT "Grosse Aufloesung"
ELSE
  PRINT "Kleine Aufloesung"
ENDIF
----

Dasselbe Prinzip kann für viele andere Eigenschaften verwendet werden.

Ein Programm könnte beispielsweise prüfen:

* welche Bildschirmauflösung aktiv ist
* welches Laufwerk verwendet wird
* ob eine benötigte Datei vorhanden ist
* wie viel Speicher noch frei ist
* welche Firmwareversion installiert ist

=== Warum schreibgeschützte Variablen?

Systemvariablen wie `MM.HRES` und `MM.VRES` werden von MMBasic bereitgestellt und enthalten Informationen über die aktuelle Umgebung.

Sie können vom BASIC-Programm gelesen, aber nicht verändert werden.

Folgender Befehl erzeugt deshalb einen Fehler:

[source,basic]
----
MM.HRES = 800
----

Die Bildschirmauflösung wird nicht durch eine Zuweisung an `MM.HRES` geändert, sondern durch die dafür vorgesehenen MMBasic-Befehle und Optionen.

=== Nicht jede MM.INFO()-Abfrage gibt es auf jedem System

`MM.INFO()` enthält eine große Zahl unterschiedlicher Abfragen. Einige davon gelten nur für bestimmte PicoMite-Varianten oder bestimmte Hardware.

Beispiele sind Informationen über:

* WLAN beim WebMite
* Akku und Ladezustand beim PicoCalc
* PS/2-Schnittstellen
* Touch-Controller
* USB-Geräte
* PSRAM

Die verfügbaren `MM.INFO()`-Parameter können sich außerdem zwischen verschiedenen MMBasic-Plattformen unterscheiden. Die in diesem Kapitel beschriebenen Funktionen beziehen sich auf den PicoMite.

Bei anderen Systemen, beispielsweise dem Colour Maximite 2, sollte deshalb immer die jeweilige Dokumentation herangezogen werden.

=== Tipps aus der Praxis

* Verwende `MM.HRES` und `MM.VRES` statt unnötig vieler fester Bildschirmkoordinaten.
* Prüfe vor dem Öffnen wichtiger Dateien, ob sie existieren.
* Verwende `MM.INFO$()` für Rückgabewerte, die Zeichenketten sind.
* Nutze `CWD$`, `MM.INFO$(CURRENT)` und `MM.INFO$(PATH)`, wenn Programme mit mehreren Dateien arbeiten.
* Zeige bei der Fehlersuche Firmwareversion, Boot-Ursache und andere Systeminformationen an.
* Verwende nur die `MM.INFO()`-Parameter, die auf der jeweiligen PicoMite-Variante verfügbar sind.

=== Probier's selbst!

Schreibe ein kleines Programm, das folgende Informationen ausgibt:

* Bildschirmbreite
* Bildschirmhöhe
* CPU-Geschwindigkeit
* Firmwareversion
* Boot-Ursache
* Laufzeit seit dem Start
* freien MMBasic-Heap
* aktuelles Laufwerk
* aktuelles Verzeichnis

Erweitere das Programm anschließend um eine Prüfung, ob eine bestimmte Datei vorhanden ist.

=== Zusammenfassung

In diesem Kapitel hast du gelernt:

* Bildschirmgrößen mit `MM.HRES` und `MM.VRES` abzufragen
* numerische Systeminformationen mit `MM.INFO()` auszulesen
* Zeichenketten mit `MM.INFO$()` abzufragen
* den freien MMBasic-Heap mit `MM.INFO(HEAP)` zu ermitteln
* CPU-Geschwindigkeit, Firmwareversion, Boot-Ursache und Laufzeit auszulesen
* Dateien und Verzeichnisse auf ihre Existenz zu prüfen
* Laufwerk und aktuelles Verzeichnis zu ermitteln
* Informationen über das aktuell geladene Programm abzufragen
* Programme automatisch an ihre Umgebung anzupassen

Mit diesen Möglichkeiten können Programme ihre Laufzeitumgebung selbst untersuchen und dadurch robuster und flexibler reagieren.
