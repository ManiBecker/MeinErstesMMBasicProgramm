=== Das große Hardware-Projekt

In den letzten Kapiteln haben wir viele wichtige Techniken kennengelernt:

* Digitale Ausgänge
* LEDs
* Digitale Eingänge
* Taster
* Analoge Eingänge
* PWM
* Töne mit `PLAY TONE`

Bisher wurden diese Techniken meist einzeln betrachtet.

Nun wollen wir sie in einem größeren Projekt kombinieren.

Dazu bauen wir ein elektronisches Gedächtnisspiel nach dem Vorbild von Simon beziehungsweise Senso.

=== Das Vorbild

Ende der 1970er Jahre erschien ein elektronisches Spiel mit vier farbigen Tasten.

Der Computer spielte eine Folge von Farben und Tönen vor.

Der Spieler musste diese Folge anschließend exakt wiederholen.

Nach jeder erfolgreichen Runde wurde die Folge um ein weiteres Element verlängert.

Mit jeder Runde wurde das Spiel schwieriger.

Das Spiel wurde unter verschiedenen Namen verkauft:

* Simon
* Senso

Bis heute zählt es zu den bekanntesten elektronischen Spielen.

=== Das Spielprinzip

Betrachten wir eine typische Spielrunde.

Runde 1:

[source]
----
Computer:
Rot

Spieler:
Rot
----

Runde 2:

[source]
----
Computer:
Rot Gelb

Spieler:
Rot Gelb
----

Runde 3:

[source]
----
Computer:
Rot Gelb Blau

Spieler:
Rot Gelb Blau
----

Nach jeder erfolgreichen Runde wird die Folge länger.

Irgendwann wird sie so lang, dass der Spieler einen Fehler macht.

Dann endet das Spiel.

=== Unsere Hardware

Wir benötigen:

* 4 LEDs
* 4 Taster
* passende Widerstände
* Steckbrett und Verbindungsdrähte
* eine für `PLAY TONE` konfigurierte Audioausgabe

Die Beispiele dieses Kapitels wurden auf einem *PicoMite HDMI/USB* überprüft.

NOTE: `PLAY TONE` verwendet die von MMBasic konfigurierte Audioausgabe.
Ein zusätzlicher Piezo an einem beliebigen GPIO-Pin ist für diese Beispiele
nicht vorgesehen.

=== Warum brauchen wir Arrays?

Der Computer muss sich die komplette Folge merken.

Beispielsweise:

[source]
----
Rot
Gelb
Blau
Gruen
Rot
Gelb
----
    
Eine einzelne Variable genügt dafür nicht.

Deshalb verwenden wir ein Array.

[source,basic]
----
DIM FOLGE(100)
----

Damit können bis zu 100 Spielschritte gespeichert werden.

=== Eine neue Farbe erzeugen

Für jede neue Runde wird eine Zufallszahl erzeugt.

[source,basic]
----
FOLGE(LEVEL)=INT(RND*4)+1
----

Mögliche Ergebnisse:

[source]
----
1
2
3
4
----

also:

[source]
----
Rot
Gelb
Gruen
Blau
----

=== Das Programm strukturieren

Unser Spiel besteht aus mehreren Aufgaben.

Deshalb teilen wir es in Unterprogramme auf.

[source]
----
Neue Farbe erzeugen

Folge anzeigen

Spielereingaben lesen

Fehler anzeigen

Spiel beenden
----

Dadurch bleibt das Programm übersichtlich.

=== Eine Farbe anzeigen

Zunächst erstellen wir ein Unterprogramm.

[source,basic]
----
SUB ZeigeFarbe(FARBE)

END SUB
----

Dieses Unterprogramm erhält eine Zahl:

[source]
----
1
2
3
oder
4
----

und schaltet die passende LED ein.

=== Rot anzeigen

[source,basic]
----
PIN(GP0)=1

PAUSE 500

PIN(GP0)=0
----

Das ist der erste Baustein unseres Spiels.

=== Unterschiedliche Töne

Jede Farbe erhält ihren eigenen Ton.

[cols="1,2"]
|===
|Farbe |Ton

|Rot
|262 Hz

|Gelb
|330 Hz

|Grün
|392 Hz

|Blau
|523 Hz
|===

Dadurch erkennt der Spieler die Farben nicht nur optisch, sondern auch akustisch.

=== Das Unterprogramm ZeigeFarbe

Das Unterprogramm schaltet die passende LED ein und erzeugt gleichzeitig den
zugehörigen Ton mit `PLAY TONE`.

[source,basic]
----
SUB ZeigeFarbe(FARBE)
  SELECT CASE FARBE
  CASE 1
    PIN(GP0)=1
    PLAY TONE 262,262,250
    PAUSE 250
    PIN(GP0)=0
  CASE 2
    PIN(GP1)=1
    PLAY TONE 330,330,250
    PAUSE 250
    PIN(GP1)=0
  CASE 3
    PIN(GP2)=1
    PLAY TONE 392,392,250
    PAUSE 250
    PIN(GP2)=0
  CASE 4
    PIN(GP3)=1
    PLAY TONE 523,523,250
    PAUSE 250
    PIN(GP3)=0
  END SELECT

  PAUSE 300
END SUB
----

`PLAY TONE` arbeitet im Hintergrund. Die Pause von 250 ms sorgt deshalb dafür,
dass die LED ungefähr so lange eingeschaltet bleibt wie der Ton ausgegeben wird.
Die anschließende Pause von 300 ms trennt die einzelnen Farben der Folge
voneinander.

=== Die komplette Folge anzeigen

Nun können wir eine gesamte Spielrunde ausgeben.

[source,basic]
----
FOR I=1 TO LEVEL

  ZeigeFarbe FOLGE(I)

NEXT I
----

Damit wird die komplette Sequenz angezeigt.

=== Die Eingabe des Spielers

Der Spieler muss die angezeigte Folge exakt wiederholen.

Dazu verwenden wir die Funktion:

[source,basic]
----
TASTE=HoleTaste()
----

Sie liefert eine Zahl von 1 bis 4 zurück.

Die Eingabe kann über die vier angeschlossenen Taster erfolgen. Zusätzlich
können auf dem PicoMite HDMI/USB die Tasten `1` bis `4` auf der Tastatur
verwendet werden. Das erleichtert das Testen des Programms, weil das Spiel
auch ohne angeschlossene Taster ausprobiert werden kann.

=== Die Funktion HoleTaste

Die Funktion wartet so lange, bis ein Taster oder die entsprechende
Zifferntaste gedrückt wird.

[source,basic]
----
FUNCTION HoleTaste()
  DO
    t$=INKEY$

    IF PIN(GP4)=1 OR t$="1" THEN
      PRINT ".";
      DO : LOOP WHILE PIN(GP4)=1 OR KEYDOWN(0)>0
      HoleTaste=1
      ZeigeFarbe 1
      EXIT FUNCTION
    ENDIF

    IF PIN(GP5)=1 OR t$="2" THEN
      PRINT ".";
      DO : LOOP WHILE PIN(GP5)=1 OR KEYDOWN(0)>0
      HoleTaste=2
      ZeigeFarbe 2
      EXIT FUNCTION
    ENDIF

    IF PIN(GP6)=1 OR t$="3" THEN
      PRINT ".";
      DO : LOOP WHILE PIN(GP6)=1 OR KEYDOWN(0)>0
      HoleTaste=3
      ZeigeFarbe 3
      EXIT FUNCTION
    ENDIF

    IF PIN(GP7)=1 OR t$="4" THEN
      PRINT ".";
      DO : LOOP WHILE PIN(GP7)=1 OR KEYDOWN(0)>0
      HoleTaste=4
      ZeigeFarbe 4
      EXIT FUNCTION
    ENDIF

  LOOP
END FUNCTION
----

Nach einem erkannten Tastendruck wartet das Programm, bis der Hardware-Taster
wieder losgelassen beziehungsweise keine Taste auf der Tastatur mehr gedrückt
wird. Dadurch wird ein Tastendruck nicht mehrfach gewertet.

`KEYDOWN(0)` liefert dabei die Anzahl der momentan gedrückten Tasten. Solange
dieser Wert größer als 0 ist, wartet die Schleife weiter.

Nach der Eingabe ruft `HoleTaste()` außerdem `ZeigeFarbe` auf. Dadurch erhält
der Spieler sofort eine optische und akustische Rückmeldung.

=== Die Eingabe prüfen

[source,basic]
----
FOR I=1 TO LEVEL

  TASTE=HoleTaste()

  IF TASTE<>FOLGE(I) THEN

    FEHLER=1

    EXIT FOR

  ENDIF

NEXT I
----

Hier findet die eigentliche Spielprüfung statt.

=== Was passiert bei einem Fehler?

Wenn der Spieler einen Fehler macht, soll dies deutlich sichtbar und hörbar
werden.

Dazu werden alle vier LEDs gemeinsam eingeschaltet und zwei unterschiedliche
Töne ausgegeben.

=== Fehleranimation

[source,basic]
----
SUB Fehleranimation(ANZAHL)
  PRINT
  PRINT "Falsche Taste!"
  PRINT

  FOR I=1 TO ANZAHL
    PIN(GP0)=1
    PIN(GP1)=1
    PIN(GP2)=1
    PIN(GP3)=1

    PLAY TONE 300,300,250
    PAUSE 200

    PIN(GP0)=0
    PIN(GP1)=0
    PIN(GP2)=0
    PIN(GP3)=0

    PLAY TONE 500,500,250
    PAUSE 200
  NEXT I
END SUB
----

Im Hauptprogramm wird die Animation dreimal ausgeführt:

[source,basic]
----
Fehleranimation 3
----

Der Spieler erkennt dadurch sofort, dass die eingegebene Folge nicht korrekt war.

=== Der Spielablauf

Unser Spiel arbeitet nun nach folgendem Schema:

[source]
----

Folge anzeigen

Spielereingaben lesen

Richtig?
 |
 +-- Ja --> Naechste Runde
 |
 +-- Nein --> Spielende
----

=== Das vollständige Programm

Nun setzen wir die einzelnen Bausteine zusammen.

Zu Beginn werden die vier LEDs als Ausgänge und die vier Taster als Eingänge
konfiguriert:

[source,basic]
----
SETPIN GP0,DOUT
SETPIN GP1,DOUT
SETPIN GP2,DOUT
SETPIN GP3,DOUT

SETPIN GP4,DIN
SETPIN GP5,DIN
SETPIN GP6,DIN
SETPIN GP7,DIN

DIM FOLGE(100)
----

Der eigentliche Spielablauf sieht vereinfacht so aus:

[source,basic]
----
LEVEL=1

DO
  FOLGE(LEVEL)=INT(RND*4)+1

  FOR I=1 TO LEVEL
    ZeigeFarbe FOLGE(I)
  NEXT I

  FEHLER=0

  FOR I=1 TO LEVEL
    TASTE=HoleTaste()

    IF TASTE<>FOLGE(I) THEN
      FEHLER=1
      EXIT FOR
    ENDIF
  NEXT I

  IF FEHLER=1 THEN
    Fehleranimation 3
    EXIT DO
  ENDIF

  LEVEL=LEVEL+1
  PAUSE 500
LOOP
----

Das vollständige Programm enthält zusätzlich eine kurze Einführung der vier
Tasten zu Beginn sowie die Möglichkeit, nach dem Spiel eine neue Runde zu starten.

=== Spielende

Nach einem Fehler wird die erreichte Runde ausgegeben.

[source,basic]
----
PRINT

PRINT "Spiel beendet"

PRINT "Erreichte Runde:"

PRINT LEVEL
----

=== Erweiterung: Highscore

Eine interessante Erweiterung wäre ein Highscore.

[source,basic]
----
IF LEVEL>BESTE_RUNDE THEN

  BESTE_RUNDE=LEVEL

ENDIF
----

Wird eine höhere Runde erreicht, kann das Programm dies als neue Bestleistung
anzeigen. Die Variable `BESTE_RUNDE` bleibt während der Programmlaufzeit erhalten.

=== Erweiterung: Höhere Geschwindigkeit

Nach jeder Runde könnte die Anzeigegeschwindigkeit erhöht werden.

Das macht das Spiel deutlich schwieriger.

=== Erweiterung: Mehr Farben

Wer möchte, kann weitere LEDs und Taster hinzufügen.

Dadurch entstehen noch längere und anspruchsvollere Folgen.

=== Erweiterung: Grafikdarstellung

Besitzt dein System einen Bildschirm, könnten die Farben zusätzlich grafisch dargestellt werden.

Damit entsteht eine moderne Version des Spiels.
